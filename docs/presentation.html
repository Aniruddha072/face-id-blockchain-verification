The problemWhy one match isn't enough

Reverse-image search can find a stranger who just looks like you.

Face search doesn't always find the actual subject, especially when a photo isn't heavily reposted or tagged. A single embedding model can confidently match the wrong person.

Confirmed by a real test run

A single model, ArcFace, passed a stranger's photo as a match under its own distance threshold. Nothing else caught it, because nothing else was checking. One confident model is not the same as one correct model.

Stage 03Ensemble verify

Three models vote. Two of three have to agree.

Every candidate is checked against ArcFace, Facenet512, and VGG-Face independently. A candidate only counts as genuinely verified if a majority agree, not just one.

Ranking still uses ArcFace's distance as the primary signal, but the agreement count travels alongside it, anchored on-chain in modelsAgreed / modelsTotal, not just kept in a local log file.

Stage 04Anchor on-chain

A minimal Solidity contract, nothing more than it needs.

storeRecord() writes the hash, the agreement count, and a timestamp. getRecord() lets anyone, including this deck's reader, read it back without a wallet.

Stage 05Prove it, from either side

Two ways to prove a record is real, not just claimed.

verify_record.py re-reads the chain from a transaction hash. The live proof viewer does the same thing from a browser, plus a client-side check against your own output file.

From the command line

python verify_record.py --tx <hash> re-reads the contract and confirms the local saved record still matches.

From the browser

Upload your photo and record JSON. SHA-256 runs locally, byte-identical to the Python hash. Nothing you upload ever leaves the page.

Security reviewFull codebase, not just the diff

Reviewed end to end. Nothing cleared the bar to file.

The pipeline, both entrypoints, the smart contract, both static pages, and secrets handling were all checked for concrete, exploitable issues, not just style.

  • OKXSS in the proof viewer: untrusted on-chain data only ever rendered through .textContent, never raw HTML
  • OKOverwrite risk in storeRecord(): not targetable, requires reproducing a record's exact bytes under SHA-256 preimage resistance
  • OKPath traversal via CLI arguments: not applicable, this is a local trusted-input tool, not a hosted service
  • OKSecrets: no hardcoded keys anywhere tracked, .env correctly gitignored

Consent & ethicsA boundary, not a footnote

Built for consenting subjects. Nothing else.

This pipeline is run only against consenting subjects with a real, findable public presence. It is not intended, and should not be used, for employment, credit, insurance, tenant-screening, or any other decision about a person without their knowledge and consent. The accuracy benchmark earlier in this deck used LFW, a public academic dataset with known ground truth, specifically to avoid testing on anyone without their consent.
